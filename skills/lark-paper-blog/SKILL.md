# 飞书论文博客

把论文整理成准确、可读、可复用的中文技术博客，并直接更新用户指定的飞书云文档。默认使用 `--as user`，只修改用户明确指定的目标文档。

## 开始前

1. 完整读取 `lark-doc` 的 `SKILL.md`，再按阶段读取其 `+fetch`、`+update`、XML 和素材插入参考；不要猜测 CLI 参数。通过当前 Agent 的技能目录定位依赖，不使用固定的个人绝对路径。未安装本地依赖时，可用 `lark-cli skills read lark-doc` 和 `lark-cli skills read lark-doc references/lark-doc-fetch.md` 等命令读取 CLI 内置文档；若两种方式均不可用，停止文档写入并说明缺少的依赖。
2. 读取 [写作风格](references/writing-style.md)。
3. 读取 [执行流程](references/workflow.md)，用于论文取证、arXiv 原图提取、飞书写入和验证。

## 默认阅读版式

以下是本 Skill 的默认阅读偏好，适用于新建论文解读和已有正文的可读性优化；用户本次另有要求时以本次要求为准。

- **开头三点概览**：论文 URL / 书签下面紧接一个高亮块，用无序列表精简概括“动机、方法、核心贡献”，每点一句，只突出最核心内容。
- **直接进入内容**：省略“本文面向……”“重点解释……”“基于 v1、发布于……、核对日期……”等开场说明。版本核验仍需完成，论文链接和必要版本信息保留在书签或来源处。
- **说明分点、流程编号**：同一标题下，有逻辑关系、各自表达一层意思的多段说明，优先用无序列表；确有先后顺序的操作流程用编号列表。
- **实现细节就近独立补充**：参数、层数、损失权重和公式解释紧跟对应模块，用独立段落或高亮块承接，不混入步骤或说明列表内部，也不默认集中移到文末。
- **降低阅读负担**：短句、短段落，一点一个重点；术语首次出现先解释，多组实验数字用表格比较。具体排法见 [写作风格](references/writing-style.md)。

## 成品要求

- 基于论文当前官方版本，覆盖动机、问题定义、核心方法、关键实现、训练/数据、实验、消融、结论和真实局限；不把摘要机械翻译成长文。
- 先解释“为什么需要这个设计”，再解释“它如何工作”。公式只保留理解方法所需的部分，并紧接直观解释。
- 用精确实验数字支撑主要结论。明确区分绝对提升与相对提升、相关性与因果性、论文结论与自己的解释。
- 插入对理解正文有直接帮助的论文原图，通常是整体架构、关键机制、训练/数据流程；实验图只在文字无法清楚表达关系时使用。
- 图片必须来自论文官方页面或源文件，先下载到任务目录、目视检查，再上传为飞书内部资源。添加中文图注并放在对应章节，不依赖外链热加载。
- 保留目标文档现有标题、论文书签、评论和有价值的资源。目标仅有标题、书签和空段落时，可精准替换空段落；已有正文时使用局部 Block 操作，不整篇覆盖。

## 工作方式

1. **观察文档**：先读目录，再按需读取全文或章节；判断是空文档、草稿还是已有成文，并记录需要保留的资源。
2. **研究论文**：优先使用 arXiv/出版方的摘要页、HTML、PDF 和源文件。确认版本号与修订日期，提炼可核验事实和必要配图。
3. **制定结构**：根据论文贡献调整章节，不强行套固定模板；保持“动机 → 方法 → 实现/训练 → 实验 → 结论”的阅读路径。
4. **撰写并写入**：使用飞书 XML；用最小安全 Block 操作更新正文。结构性写入后重新获取最新 Block ID。
5. **插图**：把选定原图放到对应标题之后或解释段附近，按 `图 N｜一句话说明其阅读重点。` 编写中文图注。
6. **验证**：重新读取目录、关键章节和每个图片 Block，确认图片 Token、图注、公式、列表、数字、顺序及 CLI warnings 均正常。
7. **交付**：返回目标飞书链接、使用的论文版本和插入的关键图类型；不要在最终回复中暴露内部下载链接或凭证。

## 边界

- 无法访问论文正文、目标文档无写权限或论文来源不可靠时，停止写入并说明缺少什么。
- 不把论文中的所有图表搬入文档，也不复制与本文方法无关的第三方示意图。
- 不为追求完整而虚构实现细节、数据口径、图注或实验结论。
