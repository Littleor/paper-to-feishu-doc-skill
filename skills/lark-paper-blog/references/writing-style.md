# 写作风格

## 定位

面向具备基本机器学习背景的读者，写成中文技术博客，而不是论文逐段翻译、新闻稿或纯摘要。语气清晰、克制、重视机制解释；允许保留常用英文术语，但首次出现时用中文说明其含义。这是内部写作定位，不要在正文中声明受众或写作目的。

## 开头：论文链接后立即给出核心概览

顺序为：现有标题 → 论文 URL / 书签 → 三点高亮概览 → 正文。保留已有书签；新建文档时添加论文书签。概览用 `<callout>` 内的无序列表，按下面的结构填写实际内容：

```xml
<bookmark name="论文标题" href="论文官方 URL"></bookmark>
<callout emoji="💡" background-color="light-gray">
  <ul>
    <li><b>动机：</b>现有方法最需要解决的一个问题。</li>
    <li><b>方法：</b>本文解决问题的核心做法。</li>
    <li><b>核心贡献：</b>最关键的新设计、发现或有证据支撑的结果。</li>
  </ul>
</callout>
```

- 每点尽量一句话。贡献只选最核心的一项，不在开头罗列全部模块、超参数和实验数字；一个关键数字确有帮助时可以保留。
- 不添加“本文面向有基础机器学习知识的读者”“重点解释……”“发布于……；核对日期为……”等开场元信息。
- 仍需核对官方版本；把可追溯的论文链接和必要版本信息放在书签或末尾来源，不用正文开场交代工作过程。
- 概览后直接进入动机或方法；确需一句导读时保持简短，避免再写一段重复概览的摘要。

## 叙事节奏

1. 先用开头高亮块建立主线，再逐节解释原因、机制和证据。
2. 在“动机”中按背景、问题、已有路线的局限、本文方案递进。各自表达一层意思的说明优先用无序列表，不因存在逻辑递进就编号。
3. 方法章节从整体到局部：先给架构或概率建模视角，再拆核心模块、损失和训练流程。
4. 每个关键设计都回答三件事：旧方法的问题、本文的做法、为什么可能有效。
5. 实验章节围绕论文主张组织，不按原论文表格顺序抄写。先写评测环境与对照，再写核心结果和机制性消融。
6. 结论重新收束主线，说明真正贡献和适用边界，不重复摘要。

## 段落、无序列表与编号步骤

- **无序列表承接说明**：同一标题下，几段围绕同一个问题展开，且各自构成一层理由、解释、发现或限制时，用 `<ul><li>` 分点。它们可以有因果或递进关系，不必是互不相关的并列项。
- **编号列表承接流程**：读者需要依次理解“输入什么 → 做什么 → 得到什么”时，用 `<ol><li>`；每步先用简短动作概括，再补一句必要解释。
- **独立段落承接局部补充**：表格导语、图片阅读提示、术语定义、公式解释和单个结论可以保留段落，不把所有文字机械变成列表。
- 使用短句、短段落，一点只表达一个重点。需要时用简短加粗词帮助扫读，避免大段连续术语或一个列表项包含数层解释。
- 多组指标、基线或消融结果使用表格；表格附近用短段落或无序列表解释该看什么、支持什么结论。

例如“为什么紧凑状态也需要分工？”下面的四层解释，适合写成四个无序项：紧凑状态如何降低规划成本；动态与外观如何竞争容量；原方法为什么未解决分配问题；本文如何引入上下文通道。保持原有逻辑和技术含义，不改成操作步骤。

## 实现细节：与模块相邻，与主线分开

- 先用步骤或说明列表讲清模块作用，再在列表结束后，用独立段落或 `<callout>` 补充实现信息。
- 常用引导为 `<b>实现补充｜编码器。</b>`、`<b>训练设置。</b>` 或 `<b>公式补充。</b>`，按内容选择，不必每节都添加高亮块。
- 层数、维度、学习率、采样设置、损失权重和较长公式不塞进编号步骤或正文说明列表；不要把实现补充嵌套为其中的子项。
- 补充紧跟相关编码器、预测器、训练或规划章节，不默认搬到文末的统一“实现补充”区。
- 公式独立展示，并紧接变量和直觉解释；主流程保持无需先读懂公式也能理解。

## 默认结构

根据论文内容增删，不要求标题逐字一致：

- 论文书签与三点高亮概览
- `动机`
- 以论文或框架名称命名的方法总览
- 2～5 个核心模块或训练范式
- `训练` / `数据`；其他实现补充跟随对应模块
- `实验`
- `结论`

正文通常使用 `<h2>` 和 `<h3>`。避免层级过深；按真实信息关系选择段落、无序列表或编号步骤。

## 技术深度

- 保留定义模型目标、核心表示或关键约束所必需的公式；使用 `<latex>`，公式之后立即解释变量与直觉。
- 不堆砌所有附录公式和超参数。实现细节只有在解释设计选择、复现要点或消融结论时才进入正文。
- 实验数字优先选择总体结果、最关键对照和能验证机制的消融。对接近饱和的指标、不同统计口径和不可直接比较的数值主动说明。
- 论文只证明相关性时，不写成因果结论；二维可视化证据不写成完全域不变。

## 表达习惯

- 先用中文说清楚概念，再保留必要的英文名称，例如“未来隐空间对齐（Future Latent Alignment）”。
- `<b>` 只强调结论性短语，不整段加粗。
- 开头的三点概览使用高亮块；实现提醒可按需另用高亮块。不要把普通正文全放进高亮块，也不重复添加另一份开头贡献清单。
- 避免宣传式词语，如“革命性”“颠覆性”；用实验与机制支持判断。

## 图片

通常选择 2～4 张：

1. 整体架构图。
2. 最关键的新模块、表示学习或训练机制图。
3. 数据/训练流程图（当它构成主要贡献时）。
4. 一张机制性实验图（仅当文字或几个数字不足以表达关系时）。

图片放在相关章节标题后或第一次解释前。图注格式：`图 N｜图展示什么，以及读者应关注什么。` 图注使用中文并保留必要术语。不要重复插入正文已经清楚表达的样例截图、大型结果表或附录可视化。

## 篇幅

以完整解释核心机制、降低阅读负担为准。普通方法论文通常约 3000～6000 个中文字符，但不是硬性下限；已讲清主线时可以更短，不为凑字数扩写 Related Work。
